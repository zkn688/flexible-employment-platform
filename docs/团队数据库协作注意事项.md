# 团队数据库协作注意事项

## 一、统一使用同一份 SQL 文件

本课程设计项目为“某市灵活就业管理服务平台”，包含用户端、企业端、管理员端。三个人开发时必须统一使用同一份数据库结构。

统一 SQL 文件：

```text
docs/sql/flexible_employment.sql
```

数据库名称：

```text
flexible_employment
```

请三位成员都使用该 SQL 文件在 Navicat 中导入数据库，避免出现表结构不一致、字段名不一致、测试数据不一致等问题。

## 二、后端开发方式约定

本组约定：三个人每个人都写自己的 Spring Boot 后端项目。

三个人分别开发：

```text
用户端后端
企业端后端
管理员端后端
```

虽然三个后端项目是独立的，但必须连接同一个数据库，并遵守同一套表结构和字段含义。

也就是说：

```text
后端项目可以分开写
数据库必须使用同一份
表名、字段名、状态值含义必须统一
```

建议端口：

```text
用户端后端：8080
企业端后端：8081
管理员端后端：8082
```

数据库连接都使用：

```text
jdbc:mysql://localhost:3306/flexible_employment
```

开发时注意：

```text
1. 三个后端项目不要使用同一个端口。
2. 三个后端都连接 flexible_employment 数据库。
3. 三个后端不要各自创建不同版本的数据表。
4. 企业端和管理员端修改数据库后，用户端会读取到对应变化。
5. 如果某个端需要新增字段，必须先和其他成员同步。
```

## 五、三端联动关系

### 1. 岗位发布与查看

```text
企业端发布岗位
  ↓
写入 job 表，audit_status = 0
  ↓
管理员端审核岗位
  ↓
审核通过后 audit_status = 1
  ↓
用户端岗位中心展示该岗位
```

### 2. 简历投递与企业处理

```text
用户端投递岗位
  ↓
写入 application 表，status = 0
  ↓
企业端查看投递记录
  ↓
企业修改 status：已查看、通过、拒绝
  ↓
用户端我的投递页面查看状态变化
```

### 3. 公告政策发布与用户查看

```text
管理员端发布公告或政策
  ↓
写入 notice 或 policy 表
  ↓
用户端公告政策页面读取并展示
```

### 4. 政策和社保审核

```text
用户端提交政策/社保申请
  ↓
写入 policy_apply 或 social_security_apply 表
  ↓
管理员端审核
  ↓
用户端查看审核状态
```

### 5. 电子合同

```text
企业端通过用户投递
  ↓
企业端生成合同
  ↓
写入 labor_contract 表
  ↓
用户端查看电子合同
```

## 六、接口和字段风格建议

建议大家统一使用以下风格：

```text
接口返回格式：code、message、data
成功 code：200
失败 code：400 或 500
分页参数：pageNum、pageSize
时间字段：使用 DATETIME
前端状态显示：根据数据库 status 字段映射中文状态
```

因为三个人分别写自己的后端，建议每个端口接口前缀区分清楚：

```text
用户端接口：/api/user/...
企业端接口：/api/company/...
管理员端接口：/api/admin/...
```

## 七、不要各自随便改 SQL

开发过程中如果某个同学需要新增字段或新增表，请先在群里说明，并同步修改统一 SQL 文件。

不要出现以下情况：

```text
某个人本地多了字段，其他人没有
某个人改了字段名，其他人接口读不到
某个人改了状态值含义，三端显示混乱
某个人删除测试数据，其他人演示没有数据
```

建议流程：

```text
1. 先讨论是否确实需要改表
2. 确定字段名和含义
3. 修改 flexible_employment.sql
4. 通知其他成员同步更新
```

## 十一、给队友的提醒

请大家开发时重点注意：

```text
1. 不要修改已有表名和字段名。
2. 不要改变已有状态值含义。
3. 如果需要新增字段，先和组员同步。
4. 三端都使用 flexible_employment 数据库。
5. 三个人各自写 Spring Boot 后端时，端口不要冲突。
6. 企业端和管理员端产生的数据，用户端会从同一数据库读取。
7. 管理员端发布公告政策后，用户端可以看到。
8. 企业端处理投递后，用户端可以看到投递状态变化。
9. 企业端生成电子合同后，用户端可以看到合同。
```

只要统一 SQL 文件和字段含义，三个人分别开发不同 Spring Boot 后端项目，也可以通过同一个数据库实现三端联动。
